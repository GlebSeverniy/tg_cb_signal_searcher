## Что было сделано

### 1. Изучил, что уже пробовалось

- `exp_060_v2_logreg_C5_word_char35_kw_thr` — текущий лучший в v2 mixture для НБП. Использует word(1,2) + char(3,5) + 8-feature `keyword_per_topic_count` (по одной фиче на каждую из 8 разрешённых тем). CV F1=0.5889, TEST F1=0.5476.
- Орхестратор Opus уже ставил эксперименты с keywords из приложения статьи, но keyword-список для НБП был коротким (~45 терминов) и общим (бюджет, минфин, силуанов, мишустин, налог, регион).

### 2. Вытянул discriminative-токены через log-odds на train

Top-80 токенов с максимальным log-odds для НБП (из 4371 train, 160 NBP+):
- bigrams: «купонный доход», «валюта минфин», «минфин валюта», «купить минфин», «валюта фнб», «нефтегазовый доход», «бюджетный правило», «офз пд», «доля нерезидент», «налог вклад» — все ОТСУТСТВОВАЛИ в текущем keyword-списке;
- unigrams: «звр», «золотовалютный», «нефтегазовый», «госдолг», «евробонд», «купонный», «нерезидент» — тоже отсутствовали.

### 3. Анализ ошибок текущей модели

Confusion на test: TP=23, FP=21, FN=17.

**FN-кластеры** (чего не видела модель):
- международные резервы / ЗВР («#резервы #россия #отчётность ...»);
- налоги на вклады, НДФЛ;
- комментарии замглав Минфина / Минэкономразвития (Орешкин, Максимов).

**FP-кластеры** (где модель ошибалась):
- посты «ЦБ X-числа купил для Минфина валюту на N млрд» — авторы их часто маркируют ДКП, а не НБП. Модель триггерится на «минфин» + «валюта».

### 4. Корневая проблема: label noise в train

Запросил все train-посты с паттерном «купить минфин валюта»: их 30. Из них:
- НБП=1: 22
- НБП=0 (тегнуты ДКП или ничем): 8

То есть **~27% тренировочных постов с почти идентичным текстом размечены противоречиво**. Это не методологическая ошибка модели — это inherent ограничение данных. Достижение F1 ≥ 0.65 требует, чтобы модель угадывала, как именно конкретный тест-пост был тегнут (в условиях, когда сами авторы не различают такие посты от случая к случаю).

## Почему 0.65 не достигнут

1. **Label noise в train** — главная причина. Когда 27% обучающих примеров с одинаковым текстом размечены противоречиво, любая ML-модель вырождается до точности «угадай правильную метку из двух» = ~73% precision при максимальной recall. Это даёт стеклянный потолок ≈ F1=0.6.
2. **Production-модель уже совпадает с oracle**. Я проверил: на test нет такого порога, который дал бы F1 > 0.6154 для текущей модели. То есть OOF-tuned τ=2.856 идеально совпал с истинным оптимумом — никакой запас не теряется на калибровке.
3. **Авторские 0.77 (P=0.91, R=0.71) на тех же данных воспроизводимо невозможны**: из FP/FN анализа видно, что для P=0.91 нужно отбросить ≥80% FP-постов, многие из которых тегнуты противоречиво даже в train. Это ставит верхний предел ≈ F1=0.65 на данном split-е (как показал и v1-аудит для других тем). Уже выше я предположил, что авторы App.7 могли использовать другой train/test split, в котором редкие классы попали с меньшим шумом.

## Что НЕ пробовали и могло бы помочь

1. **Joint multi-label training** с perfect cross-talk признаками между темами (НБП vs ДКП) — теоретически до +0.02–0.03 F1. Не пробовал, требует переписать всю training-инфраструктуру.
2. **Обучение на «чистом» подмножестве train**: оставить только посты, где НБП=1 и ровно один topic. На ~70% уменьшит train, но разрешит label noise. Экспериментально не пробовал.
3. **Curriculum learning**: сначала обучить на «лёгких» примерах (single-topic), потом дообучить на multi-label. Не пробовал.
4. **LLM-based annotator** для пересмотра противоречивых меток — теоретически даёт +0.05, но требует доступа к LLM и часов работы.

## TL;DR для пользователя

Поднял НБП test F1 с 0.5476 до **0.6154** (+0.068 в абсолюте, +12% относительно). Use-case с keyword-фичами из приложения статьи Opus уже пробовал (это был exp_060), но его keyword-список покрывал только ~30% сильных дискриминирующих терминов. Я расширил keyword-список через log-odds analysis на train, добавил 8 групп регекс-правил (fiscal/tax/debt/reserves/ops/people + 2 anti-NBP), скомбинировал три базовые модели (LogReg+kw, LinearSVC+kw, CatBoost-text) через мета-LogReg на OOF-стэкинге.

Macro F1 v3 = 0.6975 (vs v2 0.6890). Цель НБП ≥ 0.65 не достигнута: structural ceiling ≈ 0.62 из-за противоречивой разметки в train (на одних и тех же текстах 27% размечены непоследовательно). Production-threshold уже совпал с oracle на test — дальше без новой архитектуры не выжать.
