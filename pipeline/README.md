# BERT relevance corpus — документация

Важно: этот файл описывает исторический корпус и его сборку. Для текущей карты всего проекта см. `../README.md`, `../docs/DATA_SCHEMA.md` и `../docs/MODELS.md`. В финальной topic model целевые колонки - `t1_relevant` ... `t5_relevant`; `relevant` используется как служебный `OR(t1..t5)`.

**Файл:** `bert_relevance_corpus.parquet`
**Назначение:** обучающий корпус для BERT — бинарная классификация **релевантности** телеграм-постов
посылам ЦБ РФ (5 тем «индекса восприятия»). Содержит и позитивы, и негативы.

| | |
|---|---|
| Строк | **66 180** |
| Колонок | 29 |
| Размер | 26.3 МБ (parquet, zstd) |
| Позитивов (`relevant=1`) | **3 433** (5.2%) |
| Негативов (`relevant=0`) | 62 747 |
| Ключ строки | `(channel_id, message_id)` — уникален, дублей нет |
| Пустого текста | нет |

## Быстрый старт

```python
import pandas as pd
df = pd.read_parquet("bert_relevance_corpus.parquet")

X = df["text"]            # вход для BERT
y = df["relevant"]        # таргет: 1 = релевантен хотя бы одной из 5 тем, 0 = нет
```

Для «чистого» обучения без шумных негативов см. раздел **Негативы и флаг `annotated`**.

## Схема (29 колонок)

### Таргет и разметка
| Колонка | Тип | Описание |
|---|---|---|
| `relevant` | int8 | **Главный таргет.** 1 = пост релевантен ≥1 из 5 тем; 0 = нет. = `OR(t1..t5)`. |
| `t1_relevant` | bool | Тема 1 — *Ставка высокая надолго* (посыл ЦБ: «не ждите быстрого снижения ставки»). |
| `t2_relevant` | bool | Тема 2 — *Таргет 4% без вариантов* («цель по инфляции 4% не пересматривается»). |
| `t3_relevant` | bool | Тема 3 — *Сберегать сейчас выгодно* («реальные ставки положительные — несите на вклад»). |
| `t4_relevant` | bool | Тема 4 — *Инфляция от перегретого спроса* («цены растут не сами, инфляция управляема»). |
| `t5_relevant` | bool | Тема 5 — *Конец массовой льготной ипотеки* («жильё не обязано вечно дорожать»). |
| `annotated` | bool | True = пост реально проходил LLM-разметку; False = негатив, отсечённый дешёвым префильтром (в LLM не попадал). См. ниже. |
| `reasoning` | str | CoT-обоснование LLM-разметчика (одна строка на пост). Пусто (`null`) у `annotated=False`. |
| `source` | str | Из какой вырезки пост: `7days` / `5days` / `dec15` / `apr26`. |

### Поля поста (как распарсено из Telegram)
| Колонка | Тип | Описание |
|---|---|---|
| `channel_id` | int64 | ID канала. |
| `channel_name` | str | Имя канала (не уникально: напр. два разных «Лентач»). |
| `channel_type` | str | Тип канала. |
| `message_id` | int64 | ID сообщения внутри канала. |
| `message_type` | str | Тип сообщения. |
| `post_date` | str | ISO-дата с таймзоной (`2023-12-15T...`). День = `post_date.str[:10]`. |
| `post_date_unixtime` | str | Unix-время поста. |
| `edited` / `edited_unixtime` | str | Время правки (если была). |
| `from_id` | str | ID автора. |
| `text` | str | **Текст поста** (вход для BERT). |
| `text_entities` | str | Сырые entities (форматирование, ссылки) в JSON-подобном виде. |
| `reactions_total` | int64 | Сумма реакций. |
| `has_reactions` | int64 | Были ли реакции (0/1). |
| `reactions` | str | Реакции в сериализованном виде. |
| `has_media` | int64 | Есть ли медиа (0/1). |
| `poll` | str | Опрос (если есть). |
| `inline_bot_buttons` | str | Inline-кнопки (если есть). |
| `source_file` | str | Имя исходного json-дампа канала. |
| `text_hash` | str | blake2b-16 от текста (для дедупа/связки). |

> Колонки `topic_*` / `score_*` / `is_econom` (предсказания дешёвых классификаторов) в этот файл
> **не включены** — они есть в `final_100chan_labeled.parquet`, откуда брались посты.

## Темы (t1–t5)

Это 5 фиксированных посылов ЦБ РФ («индекс восприятия»), единые для всех источников.
Разметка `tN_relevant` отвечает на вопрос: «меняет ли этот пост представление обычного читателя
по теме N?» (relevance, не направление). Направление (`+/–/0`) в этот корпус не входит —
разметка `relonly`.

**Важно про `apr26`:** в исходном файле апрельского заседания темы t3 и t4 были перепутаны
местами, а тем было 6. При сборке: (1) выполнен **полный обмен t3↔t4**, (2) **t6 удалён**.
После этого t1–t5 апреля совпадают с остальными источниками. Побочный эффект удаления t6:
44 поста, релевантные **только по t6**, стали негативами (релевантных в apr26: 895 → 851).

Распределение по темам (позитивов на тему, мультилейбл — суммы пересекаются):

| t1 | t2 | t3 | t4 | t5 |
|---:|---:|---:|---:|---:|
| 1 219 | 506 | 1 302 | 648 | 738 |

> **Ревизия t1/t4 (после первичной сборки).** Темы t1 и t4 были переразмечены отдельно
> (исправление ложных срабатываний). Сняты лишние флаги: t1 2 032 → 1 219 (−813),
> t4 2 701 → 648 (−2 053); добавлений не было, t2/t3/t5 не менялись. После пересчёта
> `relevant=OR(t1..t5)` 1 824 поста, которые держались только на t1/t4, стали жёсткими
> негативами (`annotated=True`, `relevant=0`). Позитивов: 5 257 → **3 433**.
> Скрипт: `run_eval/apply_t1t4_revision.py`. Источник ревизии: `revise_t1t4/results/annotated_revised.parquet`.

## Состав корпуса (5 источников)

Даты источников **не пересекаются** — каждый пост принадлежит ровно одному источнику.

> `relevant` ниже — **после ревизии t1/t4** (см. раздел «Темы»).

| source | Заседание / период | Дни | Постов (полная вырезка) | Размечено LLM | relevant |
|---|---|---|---:|---:|---:|
| `7days` | даты-зонды вокруг разных заседаний | 7 | 19 851 | 5 829 | 1 151 |
| `7days2` | даты-зонды (вторая партия) | 7 | 17 202 | 5 454 | 659 |
| `5days` | даты-зонды | 5 | 11 534 | 3 525 | 391 |
| `dec15` | заседание 15.12.2023 | 15–19.12 | 10 357 | 6 007 | 703 |
| `apr26` | заседание 26.04.2024 | 25–27.04 | 7 236 | 7 236 | 529 |
| | | | **66 180** | **28 051** | **3 433** |

**Даты по источникам:**
- `7days`: 2023-10-15, 2023-10-27, 2024-01-16, 2024-02-16, 2024-03-01, 2024-03-22, 2024-04-03
- `7days2`: 2023-11-17, 2023-11-30, 2024-01-28, 2024-03-13, 2024-03-27, 2024-03-28, 2024-04-15
- `5days`: 2023-11-11, 2024-01-22, 2024-02-22, 2024-03-07, 2024-04-09

- `apr26`: 2024-04-25 … 2024-04-27

**Чем размечали:** `dec15` — Sonnet; `7days`/`7days2`/`5days` — Haiku (relevance-only, recall-режим); `apr26` — Haiku.

## Негативы и флаг `annotated` (ключевой нюанс для обучения)

В корпусе **два типа негативов** (`relevant=0`), различаются по `annotated`:

| Тип | Условие | Кол-во | Что значит |
|---|---|---:|---|
| Жёсткие негативы | `annotated=True`, `relevant=0` | **24 618** | LLM видел пост и решил «не релевантно» (включая 1 824 поста, потерявших флаг при ревизии t1/t4). Надёжный 0. |
| Отсечённые префильтром | `annotated=False` | **38 129** | Пост отсеян дешёвым фильтром `тема ∪ эконом` ещё до LLM; в разметку не попадал, назначен негативом по построению. |

(Все `annotated=False` имеют `relevant=0` — это гарантировано конструкцией.)

⚠️ **Caveat по чистоте негативов.** На «union-днях» (все дни `7days`, `7days2` и `5days`, а также
17–19.12 внутри `dec15`) посты-негативы с `annotated=False` отсекались дешёвым префильтром, у которого
recall ≈ 83–90%. Значит среди них есть **~10–17% реально релевантных**, ошибочно помеченных 0.
Дни 15–16.12 (`dec15`) и весь `apr26` размечались **без префильтра** — там негативы чистые.

**Рекомендации по обучению:**
- Нужны максимально чистые метки → учить/валидировать только на `annotated=True` (28 051 постов,
  3 433 поз. / 24 618 нег.).
- Нужно больше негативов и приемлема небольшая зашумлённость → брать всё (66 180), при желании
  понизить вес `annotated=False` или вынести их только в train.

## Происхождение и воспроизводимость

**Источник всех постов (включая негативы):** `final_100chan_labeled.parquet` — полная разметка
100-канального дампа (окт 2023 – апр 2024) по 7 темам + эконом-классификатору. Все 5 размеченных
файлов стыкуются с ним по `(channel_id, message_id)` на 100% (dec15 — 6007/6008; один пустой пост
без текста не вошёл).

**Как собрано:** для каждого источника взята **полная подневная вырезка** из `final_100chan_labeled`
(все посты тех дней), на совпавшие по ключу посты вшита LLM-разметка; остальные посты тех дней →
негативы (`relevant=0`, `annotated=False`). Для `apr26` перед вшиванием выполнен обмен t3↔t4 и
удаление t6.

**Скрипт сборки:** `topic_classifier_production/run_eval/build_bert_corpus.py`

**Префильтр-классификаторы (SVC + CatBoost + эконом):** в подпапке `classifiers/` рядом с этим
файлом — самодостаточный комплект моделей, исходного кода и инструкций (`classifiers/INSTRUCTIONS.md`).
Их объединение «тема ∪ эконом» и отбирало посты на LLM-разметку.

**Исходные размеченные файлы:**
- `cbr_dec15_perception_haiku_relonly_recall_7days/results/annotated_7days.parquet`
- `cbr_dec15_perception_haiku_relonly_recall_7days_2/results/annotated_7days2.parquet`
- `cbr_dec15_perception_haiku_relonly_recall_5days/results/annotated_5days.parquet`
- `annotated-sample-15-12-2023.parquet`
- `annotated_26-04-24.parquet`

## Известные ограничения

1. **Качество меток = качество LLM-разметки.** Метки взяты как есть (Haiku/Sonnet), без ручной
   правки. Спот-чек показал, что часть позитивов спорна — это свойство разметки, не сборки.
2. **Дисбаланс классов:** 8.5% позитивов. Для BERT — взвешивание классов / focal loss / сэмплинг.
3. **Шум в `annotated=False` негативах** (см. caveat выше).
4. **`reasoning` пуст у негативов** `annotated=False` (их LLM не обрабатывал).
5. Темы t1–t5 — это посылы заседания 15.12.2023, использованные как фиксированный набор для всех
   дат; для `apr26` соответствие обеспечено обменом t3↔t4 и удалением t6 (по указанию заказчика).
